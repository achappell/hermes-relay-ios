# IOS-STD-01 — Offer explicit Standard-only setup on iOS and macOS

## Approved scope

Offer HomeBridge/Standard setup; authenticate directly to supported unmodified Standard with no Home dependency. Require typed streaming, private local history and honest recovery on both Apple platforms. Voice is optional until verified. Keep credentials/history separate and never auto-fallback.

## Acceptance

- Deliver the owner-specific behavior above using unmodified Standard Hermes and the approved [delivery contract](course-correction-2026-09-23.md).
- Preserve existing story evidence and supported adapters; no automatic mode switch or replay of an uncertain turn.
- Record applicable setup, capability limits, privacy, failure and recovery behavior against the actual supported baseline.
- Record implementation, merge and physical/live acceptance separately; do not declare an unexercised gate complete.

## Dependencies

- ios:IOS-HOME-02

## Readiness

Approved backlog scope. Owning BMAD specification/readiness review must settle API details and a bounded execution plan before implementation. No implementation or runtime acceptance is claimed.

### Facts that shape this story

1. **iOS has no direct Standard transport.** `URLSessionHermesSessionClient` is the fork-only protocol-v1 relay (`hello` with `protocol_version: 1`, `hello_ack`; `Services/URLSessionHermesSessionClient.swift:204,424-428`), not Standard. `HomeBridgeSessionClient` speaks only Home's schema-1 endpoint. `HermesRelay/` contains no `/api/ws`, `/api/audio/speak-stream` or `session.create`. As on Android, this story includes a **new direct Standard transport**; TUI-STD-01 only reused a verified adapter.
2. **Earlier Apple specs forbid opening the vanilla sockets; this story supersedes that for explicit Standard mode only.** `0-I-4-apple-migrate-ios-macos-client.md:36-38,65,1463-1464` ("no Apple production or test client may open the two vanilla Hermes sockets") and `spec-standard-4-apple-migration.md:38-39` ("not opened by Home mode") protect Home mode. The approved course correction (`course-correction-2026-09-23.md:11-19`, "Explicit connection choice") requires direct Standard setup. Boundary: the sockets open only after the user selects Standard, only with that user's own Standard token, never from Home mode and never with a Home credential. The frozen 0-I-4 and STD-4 specs are not edited.
3. **The supported direct authentication mechanism is unverified, and Android's wording disagrees with the reference implementations.** Home's adapter authenticates `/api/ws` with a `token` query parameter only (`hermes-relay-home` `src/hermes_home/bridge/standard.py:379-386,3122-3149`) and sends the Hermes Profile in `session.create` params (`standard.py:1014-1019`); its audio sidecar uses `token` plus a `profile` query parameter (`standard.py:2880-2887`). The TUI likewise appends only `token` and calls it the "legacy query-token authentication mode", redacted in diagnostics (`hermes-relay-tui` `gateway_client.py:55-77,148-150`). ANDROID-STD-01 says "`/api/ws` with bearer auth". Nothing read here shows 0.21.5 accepting an `Authorization` header, so the baseline check must record the mechanism (Decision 5). This is the readiness gate left open in `course-correction-readiness-2026-09-23.md` ("verify supported direct authentication").
4. **A token in a URL is an iOS leak risk.** Connection errors reach the user and the persisted transcript as `error.localizedDescription` (`ViewModels/ConversationStore.swift:505,565,2103,3063`), and `URLError` text can include the failing URL. The authenticated URL must exist only inside the transport at connect time and never be stored, logged, journaled or surfaced.
5. **The profile model assumes the fork relay.** `RelayProfile` requires non-empty `clientID`, `deviceID` and `displayName` (`Models/RelayProfile.swift:29-74`), which are fork `hello` fields (cf. TUI BH-03). Validation accepts `ws` and `wss` and rejects only embedded user/password (`RelayProfile.swift:46-54`): cleartext `ws` and token-like query keys pass (TUI EC-01).
6. **Mode lives in the Home migration journal, which cannot carry Standard.** `AppleTransportMode` is `home | legacy` (`Models/HomeBridgeModels.swift:1351-1354`); a profile with no journal is `.legacy` (`Models/RelayProfileCollection.swift:65-67`). The journal decoder maps an unknown mode to `.legacy` (`HomeBridgeModels.swift:1289`) and forces the mode to `.legacy` for any phase other than `homeSelected` (`:1294`).
7. **Credentials share one Keychain namespace today.** The fork relay token is service `com.achappell.HermesRelayIOS.profile` with account = profile UUID (`Services/RelayConfigurationStore.swift:25,42`; `:26` is the pre-profiles `default-token`); Home device credentials use `com.achappell.HermesRelayIOS.home-device` (`HomeBridgeModels.swift:1152-1166`, service at :1153). `deleteProfile` removes only the fork slot (`RelayConfigurationStore.swift:189-196`); Home cleanup is in the view (`Views/RelayConfigurationView.swift:60-102`). The fork slot is the Legacy rollback credential that Home profiles deliberately retain (`legacyCredentialRetained`, `HomeBridgeModels.swift:1254`; `RelayConfigurationStore.swift:141,174`), so Standard must not use it.
8. **Endpoint edits keep the old token, for every mode.** `RelayConfigurationDraft.tokenToSave` reuses the stored token when the field is blank and never checks for an endpoint change (`RelayConfigurationStore.swift:451-460`; save path `Views/RelayConfigurationView.swift:1041-1057`, which reads the selected profile's token at :1046). That is the TUI BH-02 hazard, present today for Legacy.
9. **History is one always-on transcript file per profile UUID.** `ConversationPersistenceFile.url(in:for:)` is `conversation-<profileID>.json` (`Services/ConversationPersistence.swift:68-70`) and holds messages, draft, the unconfirmed-turn marker and Home recovery (`:8-26`). iOS applies complete file protection; macOS does not (`:49-59`, iOS-only). The file is deleted with its profile (`RelayConfigurationView.swift:86-92`). Editing an endpoint keeps the UUID and therefore the file (TUI BH-06 hazard). `PromptHistory` is in memory only and reset on profile change (`Views/ContentView.swift:366-369`). Unlike the prompt-only TUI and Android history, iOS keeps full transcripts.
10. **Profile switching has no guard, for any mode.** Selecting a profile runs `select` → `onSaved()` → `store.switchToSelectedProfile()` (`Views/RelayConfigurationView.swift:924-940`; `Views/ContentView.swift:346-350`), and `resetForProfileChange` clears the active turn, `isSending`, the unconfirmed marker and Home recovery in memory (`ConversationStore.swift:2771-2838`). The only guard, `homeSessionSwitchBlockedReason` (`:1366-1376`), covers Home session switching. Home persists recovery before submitting; a Legacy turn in progress persists nothing until its tail (`persistConversation()` at `:2133,2143`), so a switch can cut an active Legacy turn with no marker on disk.
11. **Lifecycle and retention are not mode-aware.** `AppleLifecycleCoordinator.deactivate` closes only the Home client (`Services/AppleLifecycleCoordinator.swift:211-237`), so a non-Home client is never closed on background. IOS-HOME-07 retention is keyed on voice work, not mode (`ViewModels/VoiceSessionCoordinator.swift:1727-1735`), and `hasLiveTransport` is true for any connected non-Home client (`ConversationStore.swift:2543-2547`). A Standard reply or hands-free session would therefore inherit background retention unless excluded (Decision 10). A non-Home client otherwise gets the generic `runReconnectLoop` (`ConversationStore.swift:2856-2870,3031`).
12. **Both platforms already permit the connection and microphone.** The sandboxed target has `network.client` and `audio-input` (`HermesRelay.entitlements`; `ENABLE_APP_SANDBOX = YES`, `Hermes Relay.xcodeproj/project.pbxproj:656,703`). macOS differs in layout, device name, Keychain accessibility and file protection only (`Views/RelayConfigurationView.swift:830,901`; `Services/RelayConfigurationStore.swift:374-390`; `Services/SecureValueStore.swift:46-48`).
13. **The socket seam has no keepalive or frame limit.** `URLSessionWebSocketConnectionFactory` uses `URLSession.shared` (`Services/WebSocketConnection.swift:21-29`) and no code sets `sendPing` or `maximumMessageSize`. It is the right test seam (`WebSocketConnectionFactory.open(urlRequest:)`).

### Boundaries carried over from TUI-STD-01 and ANDROID-STD-01

- Standard means unmodified Hermes at `/api/ws`, with response audio at `/api/audio/speak-stream`. Target baseline is the household's 0.21.5 (`v2026.9.24`, `f97608f178d1ffeca59860195ab7da295f7c8e5f`), carried from Android's 2026-10-03 record and **not independently verified here**; TUI-STD-01 and Home were verified on 0.21.1. The slice-1 baseline check verifies Apple behavior itself.
- Home calls `session.create`/`session.resume` with `{source, profile[, session_id]}` and `session.interrupt` with `{session_id}` (`standard.py:1013-1019,1571-1574`). These are Home's observed calls, not a client contract; the baseline check records what a direct client may send.
- Typed streaming is required. Structured prompts are unsupported and never treated as text.
- Never auto-switch modes, fall back, suggest the other mode as outage recovery, replay an uncertain turn, or copy history, session IDs or transcripts across modes or Standard identities. Reconnect restores transport but does not clear uncertainty; only a successful deliberate New conversation does.
- The household endpoint reaches Hermes through Home's pilot proxy, which has a known idle-upstream disconnect (Home `spec-pilot-dead-upstream-reconnect-loop.md`, per Android's record). Any such drop is ordinary transport loss (reconnect, uncertainty preserved); a proxy fix belongs to Home, not this story.
- Standard endpoints are `wss` only (Android keeps a no-cleartext policy; here iOS validation must enforce it, Fact 5). Do not change the wire protocol, remove Legacy or the fork relay (IOS-RETIRE-01), or add Home grants or rooms to Standard.

### Credentials and endpoints

- Add a **distinct Standard credential slot**: its own Keychain service (e.g. `com.achappell.HermesRelayIOS.standard`), account keyed by the local Standard profile, written through `KeychainSecureValueStore` (iOS `ThisDeviceOnly`, not synchronizable). Standard code never calls the fork-slot `loadToken`/`saveToken`/`deleteToken` and never reads Home device or admin credentials.
- Deleting a Standard profile deletes its Standard slot and every history file for it; deleting any other profile never touches either.
- The token stays out of profile JSON, transcripts, `DiagnosticsJournal`, logs, errors and state restoration. The authenticated URL is composed only in the transport (Fact 4); failures map to typed, URL-free messages.
- Changing a Standard profile's **endpoint** clears its token and requires re-entry (TUI BH-02). Changing only the Hermes Profile keeps the token and opens a different history file; if the baseline check shows tokens are Hermes-Profile-scoped, it clears the token too.
- Endpoint validation for Standard: `wss`, host required, no user/password, and no token-like query keys including percent-encoded forms (`token`, `access_token`, `key`; TUI EC-01). A trailing `/api/ws` is accepted and normalized to the canonical form; any other path is rejected, matching Home's `required_path` strictness.
- Tests prove the Standard, fork, Home device and Home admin slots never read each other.

### Sessions, reconnect and busy state

- **New conversation (Standard).** A visible action creates a fresh Hermes session. Success clears the uncertain state and inserts a local "New conversation" divider; earlier local history stays visible but is never sent. Failure keeps the turn uncertain with sending and switching blocked (TUI BH-08); Leave this conversation (below) stays available.
- **Reconnect and relaunch.** Reconnect never silently creates a session under a transcript that looks continuous. It re-attaches with the durable session reference using the baseline-verified resume operation; if resume is unsupported or fails, the app says the earlier conversation can no longer be resumed, that its last prompt was not resent, and offers New conversation. Whether the durable session reference is persisted for relaunch is Decision 12. No session listing or resume browser is in this story; missing optional listing support is reported as unavailable (course correction, direct Standard session operations).
- **Hermes still generating.** After a local-only stop (no verified remote interrupt), the app shows "Hermes is finishing the previous response" and **does not send** a new turn, typed or spoken, and never queues one; hands-free does not re-arm. The state ends when Hermes signals turn end (if the baseline shows such a signal) or when New conversation succeeds. The legacy close-and-reconnect fallback (`ConversationStore.swift:2730-2752`) is not reused: it would claim a cancellation Hermes never confirmed. A confirmed remote interrupt also ends the state.
- **Unsupported structured prompt.** Shown as unsupported and never sent as text. If the baseline finds a supported decline or cancel operation, the app uses it; otherwise the turn enters the "finishing" state above until Hermes ends or expires it, or New conversation succeeds. The UI never pretends the turn can proceed.
- **Explicit leave.** A visible **Leave this conversation** action clears the uncertain or finishing state locally, sends nothing to Hermes, keeps the transcript, and unblocks switch, edit and delete. It is the escape when Hermes is unreachable or the token was revoked, so a failed New conversation or a missing turn-end signal can never trap the user in a profile. The course correction requires it ("Resolve or explicitly leave an active/uncertain conversation before changing its connection", `course-correction-2026-09-23.md:61`); Home's equivalent is `continueWithoutResendingHomeTurn` (`ConversationStore.swift:2457`).

Recommended **A**, matching the course correction (legacy pairing UX is removed at cutover, `course-correction-2026-09-23.md:21-27`) and TUI.
8. **Behavior changes to existing modes.** Two fixes live in shared code (Facts 8 and 10): the switch guard on selection, edit and delete, and clearing the token when an endpoint is edited. Recommended **A**: each is one code path, the course correction says to resolve or leave a conversation before changing connection, and B would leave Home and Legacy cutting active turns and sending old bearers to new hosts. Under A the guard ships in slice 1 for all modes; slice 3 only adds state coverage.
9. **History when a Standard identity changes.** The old file is kept (A), deleted (B), or made viewable (C). Recommended **A**: keep it on disk until its profile is deleted, with the "kept but not loaded" notice and no viewer in this story (a viewer would be its own story). Also confirm Standard keeps iOS's existing full-transcript history (assistant text included, iOS complete file protection) rather than prompt-only history (Fact 9); macOS has no file protection today, and this story does not claim parity.
10. **Standard in the background.** Options: (A) Standard is closed on background, an in-flight turn becomes uncertain, and Standard is excluded from IOS-HOME-07 retention; (B) Standard inherits background retention. Recommended **A**, with B a follow-up once Standard voice is live-verified. Either way the lifecycle change is explicit (Fact 11).
11. **Setup connection check.** `session.create` as the check creates a remote Hermes session on every attempt, including retries (TUI and Android do this). Options: (A) accept that; (B) check with a non-creating readiness probe (Home's own probe uses `gateway.ready`/`gateway.ping`) and create a session only on first New conversation or first turn. Recommended **B** if the baseline shows the probe authenticates the token, else A.
12. **Persist the Standard session reference across relaunch.** Options: (A) store the durable session reference (an identifier, not content, never the token) in the identity-keyed file and resume on relaunch; (B) do not persist it, so each relaunch needs an explicit New conversation with the prior transcript visible. Recommended **A** only if the baseline proves resume works, else B. Home's recovery file is the precedent (`PersistedHomeRecovery`, `Models/HomeBridgeModels.swift:1308-1320`).
13. **Standard endpoint rules.** Options: (A) `wss` only, host required, the only accepted path is `/api/ws` (a bare host or an `/api/ws` suffix is normalized; any other path, including a reverse-proxy subpath, is rejected); (B) allow other paths or `ws` for private networks. Recommended **A**: it matches Home's `required_path` strictness and Android's no-cleartext policy, and a household reverse-proxy subpath is not a supported baseline. The Keychain accessibility of the new slot is the same as every existing credential (`ThisDeviceOnly` on iOS), not a new choice.

### Slices

**Slice 1 — connection and typed chat**
1. Baseline check (first).
2. Connection mode model, Standard credential slot, endpoint validation, setup choice and `StandardSetupSection` (iOS and macOS), plus README.

**Slice 2 — voice**
Tap-to-speak, response audio via `/api/audio/speak-stream`, hands-free barge-in, remote or local-only interrupt, timing-unavailable reporting, wake and hands-free blocked during uncertainty.

**Slice 3 — remaining guards and isolation**
Guard coverage for queued input, draft, staged state and hands-free armed (TUI VG-03: staged state survives a rejected switch), cross-mode and cross-identity isolation tests, macOS parity acceptance, and any TUI finding not covered in slices 1 and 2.

### Baseline check procedure (slice 1, step 1)

A script at `scripts/standard-baseline-probe.py`, run from a Mac with `uv run --no-project --with websockets python scripts/standard-baseline-probe.py` against the household endpoint, not shipped in the app. The Standard token comes from an environment variable or a hidden prompt, never argv, a file or output. It records to `validation-ios-std-01.md` with no token, transcript or audio content, and states how many remote sessions it created (it deletes them only through a supported operation):
- Which authentication is accepted: query `token`, `Authorization` header, or both (Decision 5); whether tokens are Hermes-Profile-scoped.
- Session create succeeds and returns a reference; whether `profile` is accepted and blank defaults; whether resume with the durable reference works and listing exists; whether a non-creating readiness probe authenticates (Decisions 6, 11, 12).
- A typed turn streams events in the shapes `HermesEventNormalizer` maps; note changes against 0.21.1.
- A structured prompt arrives in a recognizable form, whether a decline or cancel operation exists, and what happens if it is ignored until expiry.
- `/api/audio/speak-stream` returns streamable audio: format, sample rate, chunking, whether timing is provided. **Usable** means the existing PCM player plays it with at most a format change.
- An interrupt mid-response is acknowledged and stops generation, or is recorded as unsupported; after a local-only stop, whether Hermes signals the turn ended (otherwise only New conversation clears the busy state).
- A dropped socket then reconnect preserves the session reference and sends no prompt; idle timeout through the proxy and maximum frame size.

If audio is unusable, record it and bring Decision 1's fallback to Amanda before slice 2 starts; slice 1 (typed chat) continues.

### I/O & Edge-Case Matrix

State terms. **Active** is `isSending` or an active turn text; **uncertain** is an unconfirmed-turn marker or Home recovery; **finishing** is the Standard busy state and does not exist for Home or Legacy. Home-only controls hidden in Standard: Home sessions, open claims, approvals, Device administration and Home pairing.

| Scenario | Input / State | Expected behavior | Error handling |
|----------|---------------|-------------------|----------------|
| FIRST_SETUP | No profile | Ask HomeBridge or Standard; Standard validates, checks the connection, then saves | Invalid choice or failed check saves nothing; other profiles intact |
| CREDENTIAL_ISOLATION | Standard, fork, Home device and admin credentials exist | Each reads and deletes only its own slot | Missing Standard token shows "Add a Standard token"; never falls back to another slot |
| ENDPOINT_VALIDATION | `ws://`, user:pass, `?token=`/`%74oken=`, extra path | Rejected; `/api/ws` suffix normalized | Specific field error; nothing saved |
| ENDPOINT_CHANGE | Edit a profile's endpoint | Token cleared and re-entry required; for Standard a different history file opens | Old token never sent to the new endpoint |
| TOKEN_REDACTION | Connection fails or logs | Typed URL-free message | No token in journal, transcript or error text |
| LEGACY_PROFILE | Existing fork-relay profile | Loads as Legacy and connects as today (Decision 4) | Never classified as Standard; setup creates a new profile |
| OLD_JSON_AND_DOWNGRADE | Pre-change JSON; or Standard data opened by an older build | Old JSON loads unchanged; older build neither crashes nor drops profiles nor connects Standard as Legacy | Standard slot untouched |
| UNCERTAIN_TURN | Socket lost after prompt sent | Marked uncertain, never replayed; reconnect keeps it | Only a successful New conversation clears it |
| RESUME_LOST | Reconnect (same app run) cannot resume | "Cannot resume; last prompt not resent"; offer New conversation | No silent new session under old transcript |
| RELAUNCH | App relaunches with a Standard identity file | Decision 12A: resume the stored reference if valid, else RESUME_LOST; 12B: show the transcript and require New conversation | Never a silent new session; reference never contains the token |
| NEW_CONVERSATION | Tap New conversation | Fresh session, divider, uncertainty cleared | Failure keeps uncertainty and blocks send and switch; Leave this conversation stays available |
| BUSY_AFTER_STOP | Local stop, no verified remote interrupt | "Hermes is finishing…"; no send, typed or spoken | Cleared by turn end (if signalled) or New conversation |
| SWITCH_GUARD | Select, edit or delete while a turn is active, uncertain or finishing | Blocked with explanation and a Leave this conversation action | Session, transcript and active profile preserved |
| LEAVE | Leave this conversation while uncertain or finishing, Hermes unreachable | State cleared locally, nothing sent, transcript kept, switch/edit/delete unblocked | Never replays the prompt |
| SETUP_CHECK | Standard setup runs its check | Decision 11B: a non-creating probe, no remote session; 11A: one session per attempt | The number of remote sessions created is recorded in validation |
| HERMES_PROFILE_CHANGE | Edit only the Hermes Profile | Token kept (cleared only if the baseline shows tokens are Profile-scoped); a different history file opens; "kept but not loaded" notice | No transcript or session reference carried over |
| VOICE_SLICE1 | Standard profile before slice 2 | Voice controls hidden with a one-line explanation | No control offered that cannot work |
| STRUCTURED_PROMPT | Prompt arrives | Shown as unsupported; supported decline if any, else "finishing" state | Never treated as text; UI does not imply progress |
| BACKGROUND | App backgrounds mid-turn | Transport closed, turn uncertain, no background voice | Foreground reconnect never replays |
| MACOS_PARITY | Same flows on macOS | Same behavior and guards | Differences limited to layout, Keychain accessibility and file protection |

### Acceptance Criteria

- Given first setup with no profile, when the user continues, then (Decision 7A) they must choose HomeBridge or Standard, a fresh HomeBridge choice reaches Home pairing, and other profiles and credentials are unchanged.
- Given Standard setup with a valid endpoint and token, when the connection check succeeds, then the profile is saved with a distinct Standard credential and the mode is visible in the profile list, settings and connection status.
- Given Standard, fork, Home device and Home admin credentials, when any is read, written or deleted, then no other slot is read or changed; deleting a Standard profile removes its slot and all its history files.
- Given an endpoint that is cleartext, has embedded credentials, a token-like key (including percent-encoded) or an unsupported path, when saving, then it is rejected with a field error and nothing is stored.
- Given a connected Standard profile, when the user sends a typed turn, then text streams through the shared normalizer, the Home-only controls (Home sessions, open claims, approvals, Device administration, Home pairing) are absent with a short explanation, a test enumerating Home-only entry points confirms none is reachable in Standard, voice controls are hidden until slice 2, and a structured prompt is shown as unsupported.
- Given an endpoint edit on any profile (Decision 8A), when saved, then the old token is cleared and must be re-entered. Given a Standard Hermes Profile change, then a separate history file opens, the user is told the earlier file is kept but not loaded, no transcript or session reference carries over, and the token is cleared only if the baseline shows tokens are Profile-scoped.
- Given pre-change profile JSON, when the app launches, then every profile loads unchanged. Given a collection containing Standard data decoded by a retained copy of the pre-change decoder (the shipped builds' decoder, kept as a test fixture), then it does not fail, does not drop profiles and does not treat the Standard profile as Legacy.
- Given a turn that may have reached Hermes, when the transport drops or the app returns to the foreground, then the turn is not replayed and stays uncertain until a successful New conversation; given resume is impossible, then the app says so and offers New conversation without creating a session silently.
- Given a turn is active, uncertain or finishing (State terms), when the user selects, edits or deletes a profile, then the action is blocked with an explanation and nothing is torn down; given the user chooses Leave this conversation, then the state clears locally, nothing is sent, and the action can proceed.
- Given a local stop without a verified remote interrupt, when the user tries to send, then the app refuses until Hermes finishes or New conversation succeeds, and never claims cancellation.
- Given the app moves to the background, when a Standard turn is in flight, then the Standard client is closed, the turn is marked uncertain, and no background retention applies.
- Given each failure class (connection refused, timeout, authentication rejected, decode error, socket drop), when the failure is displayed, journaled or logged, then a sentinel token and the authenticated URL appear in none of the error text, `DiagnosticsJournal`, transcript or persisted files.
- Given slice 2 and a usable baseline, when the user speaks, then the transcript is submitted once, response audio plays from `/api/audio/speak-stream`, barge-in stops local playback, hands-free and wake cannot arm during an uncertain Standard turn, and word timing is shown as unavailable unless verified.
- Given slice 3, when queued input, a draft or staged state exists during a blocked switch, then it is preserved (TUI VG-03); and when any mode or Standard identity is selected, then no history, credential, session reference or transcript from another mode or identity is loaded.
- Given the same flows on macOS, then behavior matches iOS except layout, Keychain accessibility and file protection.
- Given the recommended Decision 11 and 12 defaults, when setup runs the check, then no remote session is created unless the baseline requires one (and the count is recorded); and when the app relaunches, then a stored session reference resumes only if valid, otherwise the app shows the transcript and requires New conversation.

### Differences from ANDROID-STD-01

- Authentication: Android says "bearer auth"; Home and the TUI use a `token` query parameter (Fact 3). Reconcile Android once the baseline settles it.
- Android's "pre-Home Profiles load as Legacy, needs setup" is Decision 4 here because iOS Legacy profiles still connect.
- Android's minimum switch guard is new on iOS for every mode (Fact 10); Decision 8 sets its scope, and also covers the endpoint-edit token reuse that exists today (Fact 8).
- iOS history is a full transcript keyed by profile UUID with always-on persistence and iOS-only file protection (Fact 9); Standard adds an identity hash and a deletion rule.
- iOS `RelayProfile` requires fork `clientID`/`deviceID`, and mode cannot live in the Home journal (Facts 5, 6); iOS also needs an explicit downgrade rule.
- iOS must cover macOS, and its lifecycle is not mode-aware: Standard needs explicit teardown and retention exclusion (Fact 11).
- Android's household-endpoint and pilot-proxy notes carry over unverified; this draft adds reconnect/resume, structured-prompt, timing and readiness-probe rules the Android spec does not state.
- Earlier Apple specs prohibit opening the vanilla sockets; this story supersedes that for Standard mode only (Fact 2).
